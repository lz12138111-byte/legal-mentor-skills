# 庭审表达与发问三步法

## 一、老师原话

> 诉讼是一门表达的艺术，对于庭审，真理是需要高效运用并精准表述的，低效等于无效的废棋。
>
> 第一步，梳理罪名要件，这是为了确定罪名的定罪逻辑点，准确寻找个案的具体涉罪事实。
>
> 第二步，在涉罪事实确定的基础上，将定罪否罪事由，梳理成表格信息，这是为了庭上可便利索引。
>
> 第三步，根据既定辩护思路，借助表格信息，设置庭上问话范围、内容、目的，并提前预演修正。
>
> 前两步是庭上质证、询问、辩论等一切庭审活动的油库粮仓；第三步是考验、体现律师主导大辩方（律师、被告）配合度、提升辩护成效的试金石。这就是此类案件，构建一个精准、完整、高效、优质辩护活动的基石。

## 二、核心理解

这段话不是文风问题，而是庭审工作流。

老师强调的不是“律师表达要漂亮”，而是：

```text
表达必须服务于庭审目标
庭审目标来自罪名要件
罪名要件落到涉罪事实
涉罪事实整理成可索引表格
表格再转化成发问、质证、辩论和被告人配合
```

换言之，庭审表达不是现场发挥，而是庭前工程。

## 三、三步法

### 第一步：梳理罪名要件

目的：

- 找到该罪名的定罪逻辑点。
- 判断控方必须证明哪些事实。
- 避免在与定罪无关的枝节上消耗庭审资源。

输出物：

| 构成要件 | 控方必须证明什么 | 案件中的对应事实 | 现有证据 | 辩方切入点 |
| --- | --- | --- | --- | --- |
| 主体 |  |  |  |  |
| 主观方面 |  |  |  |  |
| 客观行为 |  |  |  |  |
| 危害结果 |  |  |  |  |
| 因果关系 |  |  |  |  |
| 违法性/责任阻却 |  |  |  |  |

使用规则：

- 每个罪名先拆要件，再谈观点。
- 每个要件必须对应个案事实，不能停留在抽象法条。
- 庭审中只围绕能影响定罪、否罪、罪轻、量刑的要件发力。

### 第二步：将定罪否罪事由表格化

目的：

- 把庭审信息从“文章”变成“索引”。
- 让质证、发问、辩论都能快速调用。
- 避免庭上信息零散、表达低效。

输出物：

| 争点 | 定罪事实/控方逻辑 | 否罪或罪轻事实 | 对应证据 | 庭审用途 | 优先级 |
| --- | --- | --- | --- | --- | --- |
|  |  |  |  | 质证/发问/辩论/被告人陈述 | 高/中/低 |

表格中至少要标注：

- 控方要证明什么。
- 我方要否定什么。
- 哪份证据支撑我方。
- 该点用于质证、发问还是辩论。
- 该点是否值得在庭上花时间。

老师所谓“高效”，就是庭上任何一句话都能回到这个表格。

### 第三步：设置庭上问话范围、内容、目的，并预演修正

目的：

- 将辩护思路变成庭审动作。
- 让律师、被告人形成“大辩方”配合。
- 通过预演发现问题、删掉无效问题、调整问法。

输出物：

| 发问对象 | 发问范围 | 具体问题 | 问话目的 | 期待回答 | 风险回答 | 追问方案 |
| --- | --- | --- | --- | --- | --- | --- |
| 被告人 |  |  |  |  |  |  |
| 同案人 |  |  |  |  |  |  |
| 被害人 |  |  |  |  |  |  |
| 证人 |  |  |  |  |  |  |
| 鉴定人 |  |  |  |  |  |  |
| 侦查人员 |  |  |  |  |  |  |

发问设计规则：

- 每个问题必须有目的。
- 每个目的必须服务于一个争点。
- 每个争点必须回到罪名要件或量刑情节。
- 不问无法预测风险的问题。
- 不问即使答对也不能推进辩护目标的问题。
- 对被告人的发问必须提前预演，避免被告人答散、答乱、答过头。

## 四、庭审四件套

这套方法最终应生成四个庭审工具：

1. 罪名要件表
2. 定罪/否罪事由索引表
3. 庭审发问提纲
4. 质证与辩论调用表

四件套之间的关系：

```text
罪名要件表
→ 定罪/否罪事由索引表
→ 庭审发问提纲
→ 质证意见和辩论意见
```

前两项是“油库粮仓”，第三项是“大辩方配合”的试金石，第四项是庭审表达的最终出口。

## 五、低效表达的识别

以下内容应在庭前删掉或压缩：

- 与罪名要件无关的情绪表达。
- 不能改变定罪、罪轻、量刑或程序评价的事实细节。
- 只证明“当事人委屈”但不能证明法律后果的内容。
- 问了也无法控制答案的问题。
- 重复表达同一个证明目的的问题。
- 庭上临时翻材料才能找到依据的观点。

老师所谓“低效等于无效的废棋”，核心是：庭审时间、法官注意力、被告人表达能力都是有限资源。

## 六、进入 skill 的执行流程

当用户要求生成庭审发问、质证意见、辩护词或庭审预案时，skill 应按以下顺序工作：

```text
1. 识别罪名和程序阶段
2. 拆解罪名构成要件
3. 提取控方涉罪事实
4. 提取辩方定罪/否罪/罪轻事由
5. 制作定罪否罪事由索引表
6. 根据辩护思路设计发问范围
7. 为每个问题标注目的、期待回答、风险回答、追问方案
8. 生成质证和辩论调用清单
9. 输出庭前预演提醒
```

## 七、提示词模板

用户可以这样触发：

```text
请按老师三步法，基于以下案情生成庭审发问提纲：
1. 先拆罪名要件；
2. 再整理定罪/否罪事由索引表；
3. 最后按发问对象生成问题、目的、期待回答、风险回答和追问。
```

也可以这样触发：

```text
请把这份辩护思路转化为庭审工具：
罪名要件表、定罪否罪事由表、发问提纲、质证辩论调用表。
```

## 八、稳定规则

1. 庭审表达必须以罪名要件为起点。
2. 庭审事实必须表格化，便于快速索引。
3. 发问不能孤立设计，必须服务于既定辩护思路。
4. 每个问题都要标注问话目的。
5. 对被告人的问话必须提前预演，保证“大辩方”配合。
6. 删除不能服务于定罪、否罪、罪轻、量刑或程序评价的低效表达。
7. 真理需要高效运用并精准表述，庭审不是堆材料，而是调度材料。
